# 03 · 상태 끌어올리기 · 할 일 목록

예상 시간: 60~90분 (두 세션으로 나눠도 됨) · 개념: 상태 끌어올리기, 부모→자식 콜백, state를 어느 컴포넌트에 둘지, `setX(prev => …)` vs `setX(값)`, state는 스냅샷

02는 state를 거의 다 `App`에 몰아 둬도 화면이 돌아갔습니다. 이번에는 **형제 컴포넌트 여러 개가 같은 값을 필요로 하는** 상황과, 반대로 **한 컴포넌트만 알아야 하는 값**이 같은 화면에 섞여 있습니다. 어떤 기능을 만드느냐보다 **state를 어디에 두느냐**가 이번 실습의 전부입니다.

## 목표

할 일 목록. 추가 · 완료 토글 · 삭제 · 편집 · 필터.

## 시작 마크업

- `src/starters/Starter03.jsx` — 정적 화면. **http://localhost:5173/?starter=03**
- `src/data/todos.js` — `initialTodos` (할 일 3개, `{ id, text, done }`) · `morningRoutine` (문자열 3개)

> 스타터는 모양 샘플입니다. 서로 배타적인 상태(정상/오류, 목록/빈 상태, 완료 항목 있음/없음)를 한 화면에 전부 그려 두었습니다. 실제 화면에는 그중 하나만 나옵니다.

`App.jsx`는 이번 실습 화면으로 교체합니다. 02에서 만든 컴포넌트 파일은 지우지 말고 두세요 — `App`에서 참조만 끊으면 됩니다. 02의 리팩토링 후보 목록은 이번 실습과 무관하니 신경 쓰지 않아도 됩니다.

## 요구사항

### 컴포넌트 나누기 (이번 실습의 제약)

1. 최소한 다음 네 가지는 **서로 다른 파일의 컴포넌트**여야 합니다: ① 입력 폼 ② 필터 탭 ③ 목록 ④ 항목 한 줄. 하단 요약 줄은 자유입니다. (한 컴포넌트에 몰아넣으면 이번 실습의 문제 자체가 사라집니다.)

### 추가

2. 입력창에 쓰고 `추가`를 누르거나 Enter를 치면 목록 맨 아래에 추가되고, 입력창이 비워집니다. 새 할 일은 `done: false`입니다.
3. 내용이 비어 있거나 공백뿐인 채로 제출하면 **추가되지 않고** 입력창이 `input invalid`, 아래에 `help error` 안내문이 나옵니다. 다시 입력하면 안내문이 사라집니다.
4. 헤더의 `아침 루틴 추가` 버튼은 `morningRoutine`의 3개를 한 번에 추가합니다. **여러 개를 한꺼번에 넣는 코드를 새로 쓰지 말고, 할 일 1개를 추가하는 함수를 3번 호출해서** 구현하세요. (실험 12에서 이 구현을 씁니다.)

### 완료 · 삭제 · 필터

5. 각 줄의 체크박스로 완료 여부를 토글합니다. 완료된 줄은 `list-item done`이고 체크박스가 체크된 상태입니다.
6. 각 줄의 `삭제`로 그 항목만 사라집니다.
7. 탭은 `전체` / `진행중` / `완료` 3개. 선택된 탭만 `tab active`입니다. 탭 글자 옆의 개수는 계산값이고, **선택된 탭과 무관하게 항상 전체 데이터 기준**입니다.
8. 목록에는 선택된 탭에 해당하는 항목만 나옵니다.
9. 목록이 빌 때 문구가 상황에 따라 다릅니다 (스타터의 `empty` 상자 3종):
   - 할 일이 아예 없을 때 → `아직 할 일이 없습니다`
   - `진행중` 탭인데 해당 항목이 없을 때 → `진행 중인 할 일이 없습니다`
   - `완료` 탭인데 해당 항목이 없을 때 → `완료한 할 일이 없습니다`
10. 하단에 `N개 중 M개 완료`. 옆의 `완료 항목 지우기`는 완료된 항목을 모두 삭제하고, 완료가 0개면 `disabled`입니다.

### 편집

11. 각 줄의 `수정`을 누르면 **그 줄만** 입력 줄로 바뀝니다 (스타터의 편집 중 줄). `저장`은 내용을 반영하고, `취소`는 버립니다. 저장·취소 후에는 원래 줄로 돌아갑니다.
    - **한 번에 한 항목만** 편집 상태일 수 있습니다. A를 편집하다가 B의 `수정`을 누르면 A는 편집이 끝나고(저장하지 않음) B가 편집 상태가 됩니다.
    - 빈 내용으로 저장하면 저장되지 않습니다. (요구 3처럼 안내문까지 만들 필요는 없고, 저장만 막으면 됩니다.)

### 실험 (코드에 남기지 않음, 완료 보고 때 결과만)

12. 요구 4의 `아침 루틴 추가`로 실험합니다. **각 단계마다 실행 전에 예측을 먼저 적고** 나서 실행하세요.
    - (a) 1개 추가 함수를 `setTodos([...todos, 새항목])` 형태로 쓴 뒤 버튼을 누르면 할 일이 **몇 개** 늘어나나요?
    - (b) 같은 함수를 `setTodos(prev => [...prev, 새항목])` 형태로 바꾸면 몇 개 늘어나나요?
    - (c) (a) 형태로 되돌린 뒤, 세 번의 호출 사이사이에 `console.log(todos.length)`를 넣으면 세 값이 어떻게 나오나요?
    - 확인이 끝나면 `console.log`를 지우고, **올바르게 동작하는 쪽**을 최종 코드로 남깁니다.

## 완성 조건

체크하기 전에 브라우저에서 **한 항목씩 직접 해 보세요.** 01·02에서 두 번 다 실제로는 미충족인 항목을 체크한 채로 완료 보고가 왔습니다. 못 한 항목은 비워 두고 보고하면 됩니다 — 그게 감점이 아니라 리뷰 재료입니다.

- [x] 입력 폼 · 필터 탭 · 목록 · 항목 한 줄이 서로 다른 파일의 컴포넌트다
- [x] 추가 · 토글 · 삭제 · 편집 저장이 모두 동작하고, 추가 후 입력창이 비워진다
- [x] 공백만 제출하면 추가되지 않고 `input invalid` + `help error`가 나온다
- [x] `아침 루틴 추가`를 한 번 누르면 할 일이 **3개** 늘어난다
- [x] 탭 옆 개수 3개가 전부 계산값이고, 이 개수를 위한 `useState`가 없다
- [x] 탭을 바꾸면 목록이 바뀌고, 선택된 탭만 `tab active`다
- [x] 빈 상태 문구 3종이 상황에 맞게 나온다
- [x] `N개 중 M개 완료`가 맞고, 완료 0개면 `완료 항목 지우기`가 `disabled`다
- [x] 한 번에 한 항목만 편집 상태이고, A 편집 중 B의 `수정`을 누르면 A가 원래 줄로 돌아간다
- [x] 배열·객체 state를 바꿀 때 `push`, `splice`, `todo.done = …` 같은 직접 수정이 없다
- [x] 같은 state를 두 곳에 복사해 두고 양쪽을 갱신하는 코드가 없다
- [x] `npm run lint` 경고 없음, 브라우저 콘솔 경고·에러 없음 (key 경고 포함)
- [x] 스타터에 없는 태그 · className · CSS를 새로 만들지 않았다
- [x] 변하지 않는 값에 `let`을 쓰지 않았다
