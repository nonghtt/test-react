# 02 · state와 이벤트

예상 시간: 60~90분 (두 세션으로 나눠도 됨) · 개념: `useState`, 이벤트 핸들러, 제어 컴포넌트, 배열·객체 state 불변성, 파생 값, state는 스냅샷

01은 데이터를 화면으로 바꾸기만 했습니다. 이번에는 사용자가 화면을 조작하면 데이터가 바뀌고, 바뀐 데이터가 다시 화면이 되는 순환을 만듭니다.

## 목표

카페 주문 화면. 메뉴를 장바구니에 담고, 수량을 조절하고, 요청사항을 적고, 주문합니다.

## 시작 마크업

- `src/starters/Starter02.jsx` — 정적 화면. **http://localhost:5173/?starter=02**
- `src/data/menu.js` — 메뉴 6개. `{ id, name, price, emoji, description }`

> 스타터는 모양 샘플입니다. 메뉴 카드 2장·장바구니 2줄만 있고, "담긴 상태"와 "빈 상태"를 둘 다 그려 두었습니다. 실제 화면에서는 둘 중 하나만 나옵니다.

`App.jsx`는 이번 실습 화면으로 교체합니다. 01 컴포넌트 중 `Badge`는 그대로 재사용하세요. 01에서 만든 범용 부품이 다른 화면에서 실제로 쓰이는지 확인하는 기회입니다.

## 0단계 · 코딩 전에 설계를 먼저 씁니다

01에서 개념은 대화로 빠르게 잡혔는데 코드로 옮길 때 왕복이 많았습니다. 이번에는 순서를 바꿉니다. **코드를 쓰기 전에** 아래 세 가지를 짧게 적어서 Claude에게 보내고, 확인을 받은 뒤 시작하세요.

1. 이 화면에 **state가 몇 개** 필요한가? 각각 이름과 값의 모양(예: `숫자`, `{ id, qty }의 배열`).
2. state가 **아닌** 값은 무엇인가? (화면에 보이지만 state에서 계산해 낼 수 있는 값)
3. 각 state는 **어느 컴포넌트**에 두는가?

정답을 맞히는 게 목적이 아닙니다. 코드를 쓰기 전에 구조를 말로 설명하는 연습입니다.

## 요구사항

### 장바구니

1. 메뉴 카드의 `담기`를 누르면 장바구니에 추가됩니다. **이미 담긴 메뉴면 새 줄이 생기지 않고 수량만 +1** 됩니다.
2. 장바구니에 담긴 메뉴의 카드에는 `N개 담김` 배지가 보입니다. 담기지 않은 카드에는 배지가 없습니다.
3. 장바구니 각 줄의 `+` / `−`로 수량을 조절합니다. **수량이 0이 되면 그 줄이 사라집니다.**
4. 각 줄에 소계(단가 × 수량), 제목 옆에 총 수량, 하단에 합계가 표시됩니다. 셋 다 장바구니에서 계산합니다.
5. 장바구니가 비면 목록 대신 스타터의 빈 상태 상자가 나오고, 제목 옆 개수 표시는 없습니다.

### 요청사항

6. `요청사항` textarea는 **제어 컴포넌트**입니다. 입력할 때마다 아래에 `N / 50자`가 갱신됩니다.
7. 50자를 넘으면 textarea에 `invalid`, 안내문이 `help error`로 바뀌고 문구도 스타터처럼 바뀝니다. 입력 자체를 막지는 않습니다.

### 주문

8. `주문하기`는 장바구니가 비었거나 요청사항이 50자를 넘으면 `disabled`입니다.
9. 폼을 제출하면(버튼 클릭 또는 textarea에서 Ctrl+Enter 등) **페이지가 새로고침되지 않고**, 상단에 `주문 완료! N개 항목, X원` 알림이 나타나며, 장바구니와 요청사항이 비워집니다.
10. 알림은 다음에 무언가를 담으면 사라집니다.

### 실험 (코드에 남기지 않음, 완료 보고 때 결과만)

11. `담기` 핸들러에서 `set…(...)`을 호출한 **바로 다음 줄**에 장바구니 state를 `console.log`로 찍어 보세요. 방금 담은 항목이 들어 있나요? 결과를 확인한 뒤 `console.log`는 지웁니다.
