- 변하지 않는 값을 `useState`에 넣음 — "state = 시간에 따라 변하는 값" 기준이 아직 자리 잡지 않음 (00)

- `key`를 "고유한 값을 넣는 곳" 정도로만 이해 — index가 문제 되는 경우(추가·삭제·정렬 시 state가 엉뚱한 항목에 붙음)를 설명하지 못함 (00)
- prop 이름 불일치 실수 — 부모가 넘긴 이름과 자식이 받는 이름 (00, 2회)
- 완성 조건을 하나씩 대조하지 않고 "완료" 보고 — 01 1차에서 11개 중 5개 미충족 (01)
- 범용 컴포넌트에 특정 도메인 지식을 넣음 — `Badge`가 프로젝트 status를 앎 (01)
- 에러 원인을 모른 채 `?.`로 덮음 — 값이 예상과 다르면 먼저 `console.log` (01)
- early return(`if (...) return null;`)이 손에 익지 않음 — JSX 안 삼항으로만 분기하려 함 (01)
- 래퍼(컨테이너) 요소를 `map` 안팎 어디에 둘지 헷갈림 — "목록에 1개 vs 항목마다 1개" 기준 (01, 3회)

### 01 컴포넌트와 props — ✅ 보완 후 통과 (2026-09-18)

- 시작: 2026-09-17
- 출제 의도: state 없이 props 설계에 집중. `Badge`/`Section`은 사용 모양을 고정해 prop 이름을 맞추는 연습(00 약점), 나머지는 직접 설계. `count && …`의 `0` 함정, `AvatarGroup`의 early return `null`, 팀→프로젝트→태그/담당자 중첩 `key`. 스타터 오해 방지 문구를 실습과 스타터 양쪽에 명시. 질문 4번은 00의 `key` 숙제.

#### 2차 리뷰 (2026-09-18, `a127ec8`) — 통과

- **진행 과정** (세션 2일차, 질문 중심으로 진행): `children`을 문서로는 이해 못 하다가 "태그 사이 내용 = `children`이라는 이름의 prop, Vue `<slot/>` 자리에 `{children}`"으로 정리 → `Badge`를 `tone` + `children`으로 재작성 → "부모가 자식이 받는 값을 알아야 하는 게 맞나" 질문 → 컴포넌트 인터페이스 개념(HTML `type` 속성 비유) → `Section`이 `team`이 아니라 `title`/`count`/`children`을 받는 이유 → "껍데기뿐인 컴포넌트가 의미 있나" → 레이아웃 컴포넌트와 분리 기준 → `AvatarGroup` early return에서 세 번 왕복(삼항→호출부 필터→`map` 안에 div→최종).
- **최종 코드**: `Badge`(tone 4종만 앎, 모르는 값은 기본 배지), `Section`(`<section>` 껍데기 + `count > 0` 규칙 + `children`), `ProjectCard`(status→`{label, tone}` 조회 객체, 설명·태그·마감 조건부), `AvatarGroup`(`members` 배열, 없으면 반환 없음, 그룹 div 1개). 완성 조건 11개 충족, lint 통과.
- **질문 답변**: ① `children` = slot, 껍데기 재사용 — 구현으로 확인. ② `&&`는 boolean이 아닌 왼쪽 값을 반환하므로 `0`이 그려짐 → 왼쪽을 boolean으로. ③ status 지식은 한 곳(`ProjectCard`의 조회 객체)에, `Badge`는 `tone`만 — "상태값의 집중화와 자식 컴포넌트 분리 기준을 배웠다". ④ 어제 정답.
- **남은 관례** (통과와 무관): `return;` → `return null;`, `return` 뒤 불필요한 `else`, `statusConfig`가 컴포넌트 함수 안(렌더마다 재생성 — 05 렌더링 단계에서 다룸), 닫는 태그 `></X>` 대신 `<X />`.
- **약점 메모**: early return 패턴이 손에 익지 않음(설명 3회 후 성공). 구조 하나를 고치면 다른 구조가 되돌아가는 일이 잦음(래퍼 위치) — 고친 뒤 이전 지적 사항을 다시 훑는 습관 필요. 개념은 대화로 빠르게 잡지만 코드로 옮기는 단계에서 왕복이 많음 — 02부터는 "먼저 구조를 말로 설명하게 한 뒤 구현" 방식 시도.
